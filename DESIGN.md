# OnlineStore – Design Document

A full-stack e-commerce learning project: **SQL Server + ASP.NET Core Web API (C#) + React**.
Goal: build every layer yourself and be able to explain it in interviews.

---

## 1. Tech Stack

| Layer      | Technology                                   | Why                                                    |
|------------|----------------------------------------------|--------------------------------------------------------|
| Database   | SQL Server LocalDB (`(localdb)\MSSQLLocalDB`) | Free, already installed, same engine as real SQL Server |
| ORM        | Entity Framework Core 9 (Code-First)         | Maps C# classes to tables, migrations track schema      |
| Backend    | ASP.NET Core 9 Web API (Controllers)         | REST API, built-in DI, middleware, auth                 |
| Auth       | ASP.NET Core Identity + JWT Bearer tokens    | Stateless auth that works well with a React SPA         |
| Frontend   | React 19 + Vite (JavaScript)                 | Component-based SPA, fast dev server                    |
| Routing    | React Router                                 | Client-side page navigation                             |
| State      | Context API (cart), later Redux Toolkit (optional) | Share state across components                     |
| HTTP       | Axios                                        | Interceptors for JWT, cleaner than raw fetch            |
| Testing    | xUnit + Moq (backend)                        | Unit test services in isolation                         |
| Editor     | VS Code (both sides)                         |                                                         |

## 2. High-Level Architecture

```
┌──────────────────────┐   HTTP/JSON (axios)   ┌───────────────────────────┐   EF Core   ┌─────────────┐
│  React (Vite)        │ ───────────────────▶  │  ASP.NET Core Web API     │ ──────────▶ │ SQL Server  │
│  localhost:5173      │ ◀───────────────────  │  localhost:5xxx           │ ◀────────── │ LocalDB     │
│  Pages / Components  │   JWT in Auth header  │  Controllers → Services   │             │ OnlineStore │
└──────────────────────┘                       │  → Repositories/DbContext │             └─────────────┘
                                               └───────────────────────────┘
```

**Request flow (example: GET /api/products):**
1. React component calls `api.get('/products')` inside `useEffect`.
2. Request passes through the middleware pipeline (exception handler → CORS → authentication → authorization).
3. `ProductsController` receives it and calls `IProductService`.
4. The service queries the `AppDbContext` (EF Core), which translates LINQ to SQL.
5. Entities are mapped to **DTOs** and returned as JSON with status `200 OK`.
6. React stores the result in state, and the component re-renders.

## 3. Backend Folder Structure

```
Server/OnlineStore.API/
├── Controllers/        # Thin: receive HTTP, call services, return status codes
├── Services/           # Business logic (interfaces + implementations)
├── Data/
│   ├── AppDbContext.cs # EF Core DbContext
│   ├── Seed/           # Initial data
│   └── Migrations/     # Generated by `dotnet ef migrations add`
├── Entities/           # DB models (Product, Category, Order, ...)
├── DTOs/               # Request/response shapes sent over the wire
├── Middleware/         # Global exception handling
├── Helpers/            # Paging, mapping, etc.
├── Program.cs          # DI registrations + middleware pipeline
└── appsettings.json    # Connection string, JWT settings
```

**Layering rule:** Controller → Service → DbContext. Controllers never touch the DbContext directly, and entities never leave the API (DTOs are sent instead).

## 5. Database Design

### Tables

**Categories**
| Column | Type          | Notes      |
|--------|---------------|------------|
| Id     | int, PK, identity |        |
| Name   | nvarchar(100) | required, unique |

**Products**
| Column        | Type            | Notes                   |
|---------------|-----------------|-------------------------|
| Id            | int, PK, identity |                       |
| Name          | nvarchar(200)   | required                |
| Description   | nvarchar(max)   |                         |
| Price         | decimal(18,2)   | required, > 0           |
| StockQuantity | int             | >= 0                    |
| ImageUrl      | nvarchar(500)   |                         |
| CategoryId    | int, FK → Categories.Id |                 |
| CreatedAt     | datetime2       | default GETUTCDATE()    |

**Users** (via ASP.NET Core Identity: `AspNetUsers`, `AspNetRoles`, `AspNetUserRoles`)
- Roles: `Admin`, `Customer`

**Orders**
| Column      | Type           | Notes                          |
|-------------|----------------|--------------------------------|
| Id          | int, PK        |                                |
| UserId      | nvarchar(450), FK → AspNetUsers.Id |            |
| OrderDate   | datetime2      |                                |
| Status      | nvarchar(20)   | Pending / Paid / Shipped / Cancelled |
| TotalAmount | decimal(18,2)  |                                |
| ShippingAddress | nvarchar(500) |                             |

**OrderItems**
| Column    | Type          | Notes                                 |
|-----------|---------------|---------------------------------------|
| Id        | int, PK       |                                       |
| OrderId   | int, FK → Orders.Id |                                 |
| ProductId | int, FK → Products.Id |                               |
| Quantity  | int           | > 0                                   |
| UnitPrice | decimal(18,2) | price **at time of purchase** (snapshot) |

### Relationships (ER)
```
Category 1 ──── * Product
User     1 ──── * Order
Order    1 ──── * OrderItem * ──── 1 Product
```

> The cart lives on the client (Context + localStorage) until checkout, when it becomes an Order.

## 6. API Endpoints

| Method | Route                       | Auth        | Purpose                          |
|--------|-----------------------------|-------------|----------------------------------|
| GET    | /api/products               | Public      | List (paging, sort, filter, search) |
| GET    | /api/products/{id}          | Public      | Product details                  |
| POST   | /api/products               | Admin       | Create product                   |
| PUT    | /api/products/{id}          | Admin       | Update product                   |
| DELETE | /api/products/{id}          | Admin       | Delete product                   |
| GET    | /api/categories             | Public      | List categories                  |
| POST   | /api/auth/register          | Public      | Register customer                |
| POST   | /api/auth/login             | Public      | Returns JWT                      |
| POST   | /api/orders                 | Customer    | Checkout (create order)          |
| GET    | /api/orders/my              | Customer    | My orders                        |
| GET    | /api/orders                 | Admin       | All orders                       |
| PUT    | /api/orders/{id}/status     | Admin       | Update order status              |

**Status codes used:** 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.

**Paging query example:** `GET /api/products?pageNumber=1&pageSize=10&sortBy=price&search=phone&categoryId=2`

## 8. Cross-Cutting Concerns

- **CORS:** allow `http://localhost:5173` in development only.
- **Validation:** DataAnnotations on DTOs (`[Required]`, `[Range]`), plus `[ApiController]`, which returns 400 automatically.
- **Errors:** global exception middleware returns `ProblemDetails` JSON and never leaks stack traces in production.
- **Logging:** built-in `ILogger<T>`.
- **Config/Secrets:** connection string and JWT key go in `appsettings.Development.json` or user-secrets, never committed to git.
- **Async everywhere:** `async/await` with `ToListAsync()`, `SaveChangesAsync()`.

## 9. Key Interview Concepts Covered by This Project

- **C#/.NET:** DI and lifetimes (Scoped/Transient/Singleton), middleware pipeline, async/await, LINQ, IQueryable vs IEnumerable, generics, interfaces
- **EF Core:** Code-First, migrations, relationships, `Include`, `AsNoTracking`, the N+1 problem, transactions, change tracking
- **REST:** verbs, status codes, idempotency, DTOs, versioning
- **Security:** JWT, authentication vs authorization, roles, password hashing, CORS, SQL injection prevention
- **React:** components, props, state, hooks (`useState`, `useEffect`, `useContext`, custom hooks), controlled forms, routing, protected routes, the virtual DOM
- **SQL:** joins, GROUP BY/HAVING, indexes (clustered vs non-clustered), stored procedures, normalization, transactions and ACID
